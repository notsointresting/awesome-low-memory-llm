Local inference is a
memory problem.

Not all low-memory optimizations solve the same bottleneck. Explore the six approaches reshaping local AI, and see where the real open-source opportunity lies.

01 · SSD streaming

MoE experts or model layers live on flash and arrive on demand. Makes oversized models possible, but adds storage latency and disk capacity needs.

Edge0 · Colibri · MoE-Infinity

02 · Low-bit weights

Quantization and specialized kernels shrink the weight budget. Performance and quality depend on formats, architecture and calibration.

BitNet · LLM Compressor · SqueezeLLM

03 · CPU/GPU hybrid

Keep hot compute on the GPU and distribute weights or experts across CPU/host memory. Larger RAM and fast memory links still matter.

KTransformers · PowerInfer

04 · Tiny devices

Mobile/embedded runtimes optimize ARM, NPU, file size and thermal behavior. A speed claim on a flagship is not a promise for a budget phone.

MNN · LiteRT · ExecuTorch

05 · KV-cache efficiency

Long prompts and concurrency grow attention-memory demand. Compression and cold SSD KV-cache storage help context workloads without reducing the weight checkpoint.

oMLX · FlashAttention · vLLM

06 · Hardware discovery

Other tools already recommend models for a user's hardware. Our atlas specializes in the techniques and evidence behind those recommendations.

llmfit · ModelFit · Local LLM Advisor

The gap: evidence that answers real questions

Developers need to distinguish a published *test machine* from a verified *minimum RAM*, cold from warm cache, a 1.7 TB SSD requirement from an 8 GB peak RSS, and a small on-device model from frontier-scale MoE streaming.

  • Keep author reports and independently reproduced experiments visibly separate
  • Compare memory method, disk storage, model/quant, cache state and performance context
  • Do not invent missing measurements or imply cross-hardware speed rankings
